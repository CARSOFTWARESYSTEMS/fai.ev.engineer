# SIM-003 API Contract

Base path: `/api/v1/simulators/sim-003`. OpenAPI schema is auto-generated by FastAPI at `/openapi.json` (and Swagger UI at `/docs`) when the service is running.

## Authentication and entitlement

Every endpoint except `/health` requires `Authorization: Bearer <Firebase ID token>`. The token is verified via `firebase_admin.auth.verify_id_token`; the resulting `uid` is then resolved to an organisation membership and entitlement exactly as the frontend's `BatteryTrustRoute` does:

1. No/invalid/expired token → `401`.
2. No `organisationMembers` document for this `uid` → `403`.
3. No `organisations/{id}` document, or `enabledProducts` doesn't include `battery_trust` → `403`.
4. `productAccess.battery_trust.enabled === false` → `403`.
5. `productAccess.battery_trust.allowedEmails` present and the token email isn't on it → `403`.
6. `productAccess.battery_trust.allowedRoles` present and the member's role isn't on it → `403`.
7. Role not one of `engineer`/`manager`/`admin`/`owner` → `403`.

Missing/unknown entitlement data always denies — see `api/auth.py`. A `SIM003_DEV_AUTH_BYPASS=true` loopback-only escape hatch exists for local frontend development without live Firebase credentials; it is refused for any non-loopback request regardless of the flag.

## Endpoints

### `GET /health`
No auth required. Returns transport mode, broker connection state, and POC-local-only flag. Never returns credentials.

### `GET /scenarios`
Returns the seven canonical scenarios with description and expected educational outcome.

### `GET /sample`
Returns a valid example `GenerateEventsRequest` plus the list of available battery profiles.

### `POST /generate-events`
Body: `GenerateEventsRequest` (see below). Synchronous — runs the full generate→publish→observe→detect→reconcile cycle and returns the complete `RunResult` in one response. This is the source requirement's original batch workflow; use this for CLI-style one-shot calls.

### `POST /runs` → `202 Accepted`
Body: `GenerateEventsRequest`. Starts the run as a background task and returns `{run_id, status: "RUNNING"}` immediately. Use with `/runs/{id}/stream` for live progress. `409` if an identical (scenario, seed, battery_id) run is already in flight.

### `GET /runs/{run_id}`
Returns the current `RunResult` (partial while running, complete once `status` is terminal). `404` for unknown or cross-organisation run IDs — the response is identical in both cases so existence is never leaked.

### `POST /runs/{run_id}/stop`
Idempotent — cancels the background task if still running; safe to call again on an already-stopped/completed run.

### `GET /runs/{run_id}/events`
Returns the full list of `ObservedEvent`s recorded so far.

### `GET /runs/{run_id}/stream`
Server-Sent Events. Two event types:
- `event: observation`, `data: <ObservedEvent JSON>` — one per delivered/detected event.
- `event: completed`, `data: <RunResult JSON>` — terminal, closes the stream.

The browser must send the bearer token as a header (native `EventSource` can't do this), so the frontend client (`sim003Client.ts`) opens the stream via `fetch()` with a manual SSE frame parser instead of `EventSource`.

### `GET /runs/{run_id}/evidence.json` / `GET /runs/{run_id}/evidence.html`
Draft evidence export — see `docs/architecture.md` for the evidence contract. HTML is dependency-free, escapes all dynamic content, never claims QA/Architect approval.

## `GenerateEventsRequest`

| Field | Type | Constraints | Notes |
|---|---|---|---|
| `battery_id` | string | 5–64 chars, must match `^SIM-[A-Za-z0-9_-]{1,60}$` | Reserved synthetic-only namespace |
| `scenario` | enum | one of the 7 canonical values | |
| `num_events` | int | 1–1000, default 10 | |
| `delay_seconds` | int\|null | 1–300 | Only meaningful for `delayed_telemetry` |
| `replay_window_seconds` | int | 1–3600, default 300 | Only meaningful for `replay_attack` |
| `interval_ms` | int | 50–10000, default 500 | |
| `qos` | int | 0, 1, or 2, default 1 | |
| `publish` | bool | default true | `false` = dry-run, no transport I/O |
| `transport` | "mqtt"\|"in_memory"\|null | | Overrides server default for this request |
| `profile_id` | string | default `sim003_48v_demo` | |
| `seed` | int | default 42 | |
| `topic_prefix` | string\|null | max 128 chars | Compatibility field — mapped to a small server-side allowlist, never concatenated raw into a topic |

`extra="forbid"` — any unknown field (including `organisation_id`, broker host/credentials, `simulated`, `retain`) is rejected with `422` rather than silently ignored.

## Error model

- `422` — Pydantic validation failure, body: `{"detail": "Invalid request", "errors": [...]}`.
- `401` — missing/invalid bearer token.
- `403` — authenticated but not entitled (see precedence above).
- `404` — unknown or cross-organisation run ID.
- `409` — duplicate concurrent run for the same (scenario, seed, battery_id).
- `413` — request body over 64 KiB.
- `429` — more than 10 concurrent runs already in flight.

## Compatibility

`/generate-events` (canonical) covers the source requirement's `/simulate` naming ambiguity — no separate `/simulate` route exists in this implementation since none was previously shipped to alias.
